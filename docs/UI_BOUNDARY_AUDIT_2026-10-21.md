# 欧包音乐 · 布局边界缺陷审查（第二轮）

> 审查时间：2026-10-21
> 视角：布局边界（滚动容器、溢出裁切、元素与容器边缘对齐、断点切换、浮层视口边界、文本截断、命中区、z-index 遮挡）
> 运行态：Electron 1220×780（默认）、1040×680（CDP 设备模拟）
> 方法：CDP 计算样式/几何批量扫描 + 逐页运行态实测 + 真实窗口截图

---

## 0. 结论

上一轮修的是"设计语言"和"明显错位"，这一轮专查**几何边界**：元素有没有越过容器、有没有互相压住、断点切换后有没有被裁掉。

共确认并修复 **12 项真实缺陷**，其中 4 项是用户能直接看到的错位：

1. 筛选胶囊条在**三个页面**都比表格/卡片宽 4px（负边距导致）；
2. 首页有 **5 个高度为 0 的空区块**，白占 120px 垂直空间；
3. 「回到顶部」与「定位播放」两个浮动按钮**垂直重叠 3px**；
4. 侧栏折叠后主内容**不跟随左移**，回收的 180px 完全浪费。

另有 12 项经实测确认**不是缺陷**（见第 3 节），避免误改。

## 3. 实测确认「不是缺陷」的项

以下都在扫描中被标记，逐项复核后确认是设计意图或测量伪影，**未改动**：

| 项 | 实测 | 结论 |
| --- | --- | --- |
| `hero-billboard` `scrollH 339 > clientH 258` | 溢出量来自 `.hero-backdrop` 的 `inset: -20%` | 背景层本就该被 `overflow: hidden` 裁掉，非文本裁切 |
| `media-title` `scrollH 60 > clientH 40` | `-webkit-line-clamp: 2` | 有意的两行截断 |
| `chart-card-desc` 1.7 行 | 实际 h=33px = 2 × 16.56px，`scrollH` 更大是 clamp 的正常表现 | 正确显示 2 行 |
| `song-row-artist-link` 20px 高 | 已有 `::after { inset: -7px -3px }` 把命中区扩到 34px | 命中区达标（扫描器未计伪元素） |
| `song-row-meta` `align-items: normal` | 只含两个 span，且是 `flex-direction: column` | 单行文本下无影响 |
| 表格首屏最后一行被播放坞压住 | 主内容 `padding-bottom: 114px`，滚到底部时最后一行距坞 54px | 滚动视口的正常遮挡，不是裁切 |
| 货架 `lastCardClipped` | 内容 2240 / 容器 882，横向滚动 | 滚动容器的预期行为 |
| 卡片网格右缘 `rightGap: 0` | 204×4 + 22×3 = 882 | 精确对齐 |
| 窗口控制额外 14px 间距 | `margin-left: 6px` | 有意把关闭按钮与功能区隔开 |
| 抽屉高度只有 337px | `bottom: auto` + 内容自适应 | 4 首歌就该这么高 |
| `scroll-to-playing-btn` 隐藏时 40px | `scale(0.88)` 过渡态 | 可见时恢复 46px |
| `.song-table-header` 在 1040 测到 690 vs 712 | `Emulation` 切换中的过渡帧 | 稳定后同为 860（@1220） |

## 6. 已知残留

1. **登录态布局未验证**：当前无可用账号，登录后的侧栏账号卡、收藏歌单列表、每日推荐等区域的边界未经实测。
2. **超长标题压力测试**：用真实数据验证了截断，但没有构造 100+ 字符的极限字符串测多行 clamp 的表现。
3. **`PrintWindow` 伪影**：多次出现整层 chrome 丢失、竖线、文字残影；已在每处用 CDP `Page.captureScreenshot` 交叉验证，最终视觉以 CDP 截图为准。
4. **1040 以下断点**：仅验证到 1040×680（应用最小窗口），未测 900px 级窄窗（已低于最小尺寸，不可达）。
